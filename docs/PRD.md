## 1. 产品愿景

### 1.1 一句话定位
> **「打开就能用，看完就懂你」的 macOS 视频播放器。**

### 1.2 设计哲学

- **极致简洁派**：参考 Apple TV App 与 macOS 系统级应用，零冗余，零打扰。所有功能让位于内容本身。
- **AI 是空气而非按钮**：智能能力默默在后台工作，用户感知到的是"我想要的，它已经准备好"，而不是"这里有个 AI 按钮"。
- **原生即美**：充分利用 SwiftUI、Metal、Core ML、Apple Neural Engine，形成与 macOS 浑然一体的质感。
- **隐私优先**：所有 AI 推理默认本地完成，云端是用户主动选择的扩展能力。

### 1.3 与竞品的差异化

| 竞品 | 我们的差异 |
|---|---|
| **IINA** | UI 更克制；AI 智能管理是一等公民 |
| **Infuse** | 不依赖云端订阅；本地媒体库 + 离线 AI |
| **VLC** | 视觉质感与体验提升一个数量级 |
| **Apple TV App** | 完全开放本地媒体；可扩展插件生态 |

## 2. 用户画像与场景

### 2.1 目标用户

- **核心用户**：拥有数百至数万部本地视频（电影、剧集、教程、个人录像、动漫）的 Mac 用户。
- **次级用户**：内容创作者（需要快速浏览素材）、隐私敏感用户、技术爱好者（喜欢插件生态）。

### 2.2 关键使用场景

| # | 场景 | 痛点 | 我们的解法 |
|---|---|---|---|
| S1 | 海量视频里找"上周拍的猫的视频" | 文件名混乱，肉眼翻找太慢 | AI 分类 + 自然语言搜索 |
| S2 | 看 2 小时讲座，只想看重点 | 拖进度条凭运气 | AI 智能摘要 + 章节标记 |
| S3 | 看外语影片缺字幕 | 找字幕、对时间轴痛苦 | Whisper 一键生成 + 翻译 |
| S4 | 一部电视剧追了一半换设备 | 不记得看到哪一集第几分钟 | 续播 + iCloud 同步 |
| S5 | 想跳过片头片尾 | 每集手动拖 | 学习用户跳过行为，自动跳 |
| S6 | 想找"包含某个人"的所有视频 | 完全做不到 | 人脸聚类 |
| S7 | 把视频投到电视看 | 投屏体验差 | AirPlay + 媒体库无线访问 |

## 4. 详细功能规范

### 4.1 播放内核（P0）

#### 4.1.1 解码与渲染
| 项 | 规范 |
|---|---|
| 视频容器 | MP4 / MKV / MOV / AVI / WebM / TS / FLV / RMVB |
| 视频编码 | H.264 / H.265 / AV1 / VP9 / ProRes，全部硬解优先 |
| 音频编码 | AAC / AC3 / E-AC3 / DTS / DTS-HD / FLAC / Opus / TrueHD |
| HDR | HDR10 / HDR10+ / Dolby Vision Profile 5 & 8 |
| 字幕 | SRT / ASS / SSA / VTT / PGS / SUP / 内嵌轨道 |
| 渲染管线 | Metal 直接渲染，色彩管理交由 ColorSync |

#### 4.1.2 播放控制
- 倍速：0.25x / 0.5x / 0.75x / 1x / 1.25x / 1.5x / 1.75x / 2x / 3x / 4x（不变调）
- 帧步进 / 帧后退（`,` / `.`）
- A-B 循环
- 视频比例：原始 / 16:9 / 4:3 / 自定义裁切
- 音视频同步偏移（±5ms 精度）
- 字幕样式自定义（字体 / 大小 / 阴影 / 描边）

#### 4.1.3 视觉与交互
- **沉浸式播放窗口**：边框 0px，控制条悬停浮现，2 秒不动自动隐藏
- **手势**：双指上下调音量 / 左右调进度，三指滑动切上下集
- **触控板灵敏度跟随系统**
- **HDR 标识**：右上角微小图标显示当前 HDR 元数据
- **截图**：⌘⇧S 截当前帧（含字幕可选），⌘⇧G 录制 GIF（最多 30s）

#### 4.1.4 AI 实时画质增强（P0）

> 让 480p 老 DVD、低码率手机录像、灰蒙 SDR 影片，**在播放当下**焕发新生。所有处理实时进行，可一键开关，CPU/GPU 占用透明可见。

**A. 增强滤镜清单**

| 滤镜 | 模型 / 算法 | 适用 | 性能成本（M1） |
|---|---|---|---|
| **超分辨率（实写）** | Real-ESRGAN-General-x2 → Core ML | 老电影、DVD、低码率视频 | 1080p 输入实时，4K 需 M2+ |
| **超分辨率（动漫）** | Anime4K v4 / waifu2x → Metal | 番剧、二次元 | 1080p→4K 实时（M1 充足） |
| **AI 降噪** | NAFNet / SCUNet → Core ML | DVDrip 雪花点、压缩伪影 | 实时 1080p |
| **HDR → SDR** | 自适应 ACES tone-mapping + AI 局部对比度 | 在 SDR 屏看 HDR 片不再灰 | 极低（GPU shader） |
| **SDR → HDR** | iSDR2HDR（轻量推理） | 老片在 HDR 屏看更鲜活 | 中等 |
| **插帧** | RIFE-v4.6（轻量） / VFI Core ML | 老剧 24→60fps 丝滑 | 1080p→60 实时（M2+） / M1 限 720p |
| **去隔行** | YADIF + AI 边缘修复 | DVD / 老电视录像 | 实时 |
| **去抖动** | 视频稳定（用于个人录像） | 手持手机视频 | 实时 720p |
| **色彩还原** | DeOldify-Lite | 黑白老片上色 | 准实时（轻微缓冲） |
| **画面锐化** | CAS（AMD Contrast Adaptive） | 通用提升清晰度 | 几乎无成本 |

**B. 渲染管线集成**

```
解码后 YUV / NV12 帧
    ↓
[硬件解复用 + 颜色空间转换]
    ↓
┌──── 增强链（用户配置顺序）────┐
│ 1. 去隔行 / 去抖           │
│ 2. AI 降噪                 │
│ 3. 超分辨率                │
│ 4. 插帧                    │
│ 5. HDR/SDR 转换 + 色彩     │
│ 6. 锐化                    │
└────────────────────────────┘
    ↓
Metal 直接渲染到屏幕
```

- 全程 GPU/ANE 共享纹理，避免 CPU 来回搬运
- 每个滤镜独立开关 + 强度滑条（0-100%）
- 模型按需下载，未下载滤镜显示「下载 280MB」按钮

**C. 智能预设（自动决策）**

进入视频时根据元数据自动建议：

| 视频特征 | 推荐预设 |
|---|---|
| ≤480p 实拍 | 老片救星：超分 + AI 降噪 + 锐化 |
| ≤720p 动漫 | 番剧增强：Anime4K + 锐化 |
| HDR 片 + SDR 屏 | HDR 兼容：tone-mapping |
| 24fps 动作片 + 高刷屏 | 丝滑插帧：RIFE 60fps |
| 黑白老片 | 时光复刻：上色 + 降噪 + 超分 |
| 4K HDR 原盘 | **关闭所有增强**（保真优先） |

用户可一键应用，也可手动微调。

**D. UI 入口**

- 播放器右下角「✨」按钮（亮色 = 已启用）
- 点开浮窗显示：当前预设 / 各滤镜开关 / 强度 / **实时性能仪表**（GPU 占用 / 帧延迟 / 温度）
- 命令面板 `⌘E` 直达「画质增强」面板
- 设置 → 画质：每个媒体类型默认行为 / 模型管理

**E. 性能保护**

- **温控感知**：检测到 SoC > 90°C 自动降级（关闭最重的滤镜）+ 顶部黄条提示
- **续航模式**：电池供电时默认关闭重型滤镜（插帧 / HDR↔HDR）
- **基准测试**：首次启用某滤镜先跑 5s 测试，预测能否实时；不能则提示用户
- **回退**：实时性能不足时自动降画质（如 4K→1440p 处理后 upscale 显示）

**F. 性能目标**

| 设备 | 1080p 实时 | 4K 实时 |
|---|---|---|
| M1 | 超分 + 降噪 + 锐化 | 仅 tone-mapping + 锐化 |
| M2 / Pro | 超分 + 降噪 + 插帧 + 锐化 | 超分 + 锐化 |
| M3 / M4 Pro+ | 全套 | 超分 + 降噪 + 锐化 |

**G. 隐私 & 体积**

- 全部本地推理，不上传任何画面
- 模型按需下载（合计约 800MB-1.5GB），可单独卸载
- 模型更新通过 macOS 后台静默 OTA
- **重型任务可卸载到 HiPixel 远程节点**（详见 §4.1.6）

#### 4.1.5 智能音量与对话增强（P0）

> 解决三个最痛的音频痛点："对话听不清，爆炸震破耳"、"片子之间音量参差"、"晚上不敢开声"。

**A. 三大核心能力**

**A.1 响度归一化（EBU R128 / ReplayGain）**
- 后台离线扫描每部视频的整体响度（LUFS）
- 播放时实时增益补偿，**所有片子都对齐到 -23 LUFS**（影院标准）
- 不同片子之间切换音量稳定，再也不用手忙脚乱
- 用户可设目标响度（-23 / -16 / -14 LUFS）

**A.2 对话增强（Voice Boost）**
- AI 模型实时分离人声与背景音（Demucs Lite / Spleeter Core ML）
- 人声单独提升 3-12dB（用户滑条调节）
- 中频补偿（1-3kHz）+ 动态压限
- 适合：嘈杂环境 / 听力下降 / 外语片想听清原声

**A.3 深夜模式（动态范围压缩）**
- 三档预设：「轻度」（-6 dB 压缩比 2:1）/「中度」（4:1）/「深夜」（8:1 + 上限 -12dB）
- 爆炸 / 枪声 / 突发高峰**自动压制**，对话**自动提升**
- 一键 `⌘⇧M`（夜间）开关
- 与「对话增强」可叠加，专治"凌晨看猛片邻居砸墙"

**B. 进阶功能**

| 功能 | 说明 |
|---|---|
| **3D 虚拟环绕** | 耳机也有 5.1 / 7.1 体验（HRTF + 房间模拟） |
| **AirPods 空间音频** | 头部追踪自适应（macOS 系统级集成） |
| **环境降噪适配** | 检测环境噪音（可选麦克风采样）→ 动态调整增强强度 |
| **多设备 EQ 预设** | 内置常见耳机 / 音箱型号补偿曲线 |
| **音轨混音** | 多音轨视频可独立调节各轨道音量（导演评论 + 原声混播） |
| **延迟补偿** | 蓝牙耳机自动检测延迟并补偿字幕同步 |

**C. 渲染管线**

```
解码后 PCM 音频
    ↓
[1] 响度增益（ReplayGain 标签或实时 EBU R128）
    ↓
[2] 对话增强（人声分离 + 提升）
    ↓
[3] 动态压缩（深夜模式）
    ↓
[4] EQ / 房间模拟 / HRTF
    ↓
[5] 空间音频处理（如启用）
    ↓
AVAudioEngine → 输出设备
```

- 全链路低延迟（< 30ms）
- 全部本地处理，AI 模型 ANE 推理

**D. 智能预设**

| 场景 | 预设 |
|---|---|
| 客厅大屏 | 影院模式：对齐 -23 LUFS + 全动态范围 |
| 笔记本扬声器 | 笔记本增强：对话 +6dB + 中度压缩 + 频响补偿 |
| 耳机 | 耳机优化：HRTF + 对话 +3dB + 轻度压缩 |
| 深夜 | 深夜模式：对话 +9dB + 强压缩 + 上限 -12dB |
| 学外语 | 听力训练：人声完全干净 + 背景 -12dB |

切换设备时自动联动（连耳机自动切耳机预设）。

**E. UI 入口**

- 播放器右下角「🔊」按钮（旁边的小图标显示当前预设）
- 浮窗：响度归一化开关 / 对话增强滑条 / 深夜模式三档 / 当前设备预设
- 实时电平表（峰值 + RMS）+ 当前 LUFS 显示
- 命令面板 `⌘⌥A`「音频增强」直达
- `⌘⇧M`（夜间）一键深夜模式

**F. 离线扫描策略**

- 入库时自动扫描 EBU R128（约视频时长的 5% 时间，后台跑）
- 扫描结果存入数据库，下次播放即时生效
- 网盘视频：仅在用户首次播放时扫描，结果缓存
- 用户可在设置 → 音频 → 「重新扫描全部」

**G. 性能目标**

| 指标 | 目标 |
|---|---|
| 对话增强延迟 | < 30ms（Demucs Lite） |
| EBU R128 扫描速度 | 实时的 20 倍（10min 视频 30s 扫完） |
| 深夜模式延迟 | < 5ms（DSP，无 AI） |
| AirPods 空间音频开销 | 由 macOS 接管，App 几乎为 0 |

**H. 隐私**

- 全部本地，无音频上传
- 麦克风环境采样可选关闭，默认关闭
- 用户可关闭所有增强，恢复纯净原音

#### 4.1.6 HiPixel 远程算力节点（P0）

> 让 MacBook 把重型 AI 任务外包给家里的 Windows / Mac mini。本地 + 远程，自动按场景调度。

**A. 设计原则**

- **零配置发现**：局域网 mDNS 自动找到 HiPixel 节点
- **场景化路由**：实时观看用本地，离线批处理走远程
- **无缝降级**：节点离线时自动回落本地或排队
- **隐私默认本地**：没显式连接节点之前，所有 AI 任务都在本机
- **凭据独立**：节点密钥与用户账号解耦，每节点独立信任

**B. 节点类型**

| 类型 | 协议 | 适用 |
|---|---|---|
| **本机内核** | 进程内调用 | 默认，零延迟 |
| **局域网节点** | HTTP / SSE + mDNS 发现 | 家里的 Windows RTX / Mac mini |
| **公网节点** | HTTPS + WireGuard / Tailscale | 出差时连家 |
| **托管 SaaS** | HTTPS + OAuth + API Key | 偶发大任务 |

**C. 添加节点流程**

**自动（局域网）**：
1. HiPixel 在 Windows 上启动 → 局域网 mDNS 广播 `_hipixel._tcp.local`
2. HiVideo 设置 → 算力节点 → 自动出现一行候选
3. 用户点「连接」→ HiPixel 弹通知"MacBook-Hikari 请求连接，是否信任？"
4. Windows 端确认 → 返回一次性配对码
5. HiVideo 输入配对码 → 双向 mTLS 证书交换 → 信任建立
6. 整个过程不输入密码、不打开端口

**手动（公网）**：
1. 输入域名 / IP + Token
2. 测试连接
3. 命名（如"家里-RTX4090"）

**D. 连接质量探测**

每个节点持续探测：
- 在线状态（绿 / 黄缓慢 / 红离线）
- RTT 延迟
- 上下行带宽
- 当前 GPU 利用率
- 队列长度
- 显卡型号 / 显存
- 当前可用预设

UI 实时显示，让用户知道"现在发过去合不合适"。

**E. 任务路由策略（核心）**

```
用户触发 AI 增强任务
    ↓
根据「任务大小 × 网络条件 × 用户偏好」选节点
```

| 任务类型 | 默认路由 |
|---|---|
| 实时观看时画质增强 | **本地**（延迟敏感） |
| 实时字幕生成 | **本地**（隐私 + 延迟） |
| 入库扫描 / 缩略图 | **本地**（数据量小） |
| 一次性 AI 字幕全片 | 本地 + 可选远程 |
| 视频摘要 | 视片长决定 |
| **AI 画质增强出片** | **远程优先**（重型，离线友好） |
| AI 剪辑高光 | 远程优先 |
| 角色识别 / CLIP 嵌入批扫 | 远程优先（大批量） |

用户可在每个 AI 功能旁选「本地 / 远程 / 自动」。

**F. 文件传输策略**

发到远程节点时，三选一：

1. **直接上传**（适合小文件 / 远程节点能访问外网）
2. **共享网盘传递**（推荐，HiVideo 把文件放进双方都能访问的 SMB / WebDAV / S3，节点拉取）
3. **节点直拉源文件**（最优，节点已配置 SMB 凭据时直接从 NAS 拉）

### 4.3 AI 智能层（P0 / 核心差异化）

#### 4.3.1 部署原则

- **云端可选**：用户在设置中可启用云端增强（OpenAI / Anthropic / 自托管 Ollama）
- **任务队列**：后台任务不阻塞播放，闲时调度（Mac 充电 + 锁屏时优先）

#### 4.3.2 模型清单

| 模型 | 用途 | 本地大小 | 推理后端 |
|---|---|---|---|
| CLIP ViT-B/32 (Core ML) | 视频/帧嵌入 | ~150 MB | ANE |
| YOLOv8-Seg (Core ML) | 物体识别 / 场景分割 | ~22 MB | ANE |
| ArcFace (Core ML) | 人脸特征 | ~95 MB | ANE |

| MiniLM (Sentence-BERT) | 文本嵌入 | ~80 MB | ANE |
| 可选：Llama 3.2 3B / Qwen 2.5 3B | 摘要 / 自然语言理解 | ~2 GB | Metal + ANE |
| Real-ESRGAN-General-x2 | 实拍超分辨率 | ~67 MB | ANE |
| Anime4K v4 / waifu2x | 动漫超分 | ~30 MB | Metal |
| NAFNet / SCUNet | AI 降噪 | ~120 MB | ANE |
| RIFE-v4.6 (Core ML) | 视频插帧 | ~45 MB | ANE |

#### 4.3.3 功能详述

**A. 自动分类**
- 入库时抽取关键帧（场景检测 + 等距采样，不超过 20 帧/视频）
- CLIP 嵌入 → HDBSCAN 聚类
- 类别名由 LLM 生成或用户自定义模板

**B. 自然语言搜索**
- 输入示例："海边日落的镜头" / "我在巴黎拍的视频" / "讲解 Swift 的部分"
- 文本 → CLIP 文本嵌入 → 向量库相似度检索 → 返回视频 + 时间戳
- 结果展示：视频缩略图 + 高亮片段，点击直接跳转播放

**C. 智能字幕（概要）**
- Whisper 本地转写 / 在线字幕搜索下载 / AI 辅助对齐
- 详细规范见 §4.4「字幕子系统」

**D. 视频摘要**
- 关键帧抽取 + 字幕全文 → LLM 摘要
- 输出：3 句话总览 / 章节列表（含时间戳）/ 30 秒高光片段
- 摘要可作为视频元数据保存，下次直接读取

**E. 智能跳过**
- 同一剧集内对比首尾片段相似度 → 候选片头/片尾
- 学习用户手动跳过行为 → 自动化
- 提示式跳过（"3 秒后跳过片头" + 取消按钮），不强制

**F. 角色识别与分组（Character Recognition）**

> 不只是"这个人"，而是"这是谁"。从匿名人脸聚类升级到具名角色识别。

**F.1 概念区分**

| 概念 | 含义 | 输出 |
|---|---|---|
| **人脸聚类**（Face Clustering） | 把同一张脸归到一组，身份未知 | "未知人物 #1" |
| **人物识别**（Person ReID） | 跨镜头、跨服装识别同一个人（结合体型/步态/服饰） | "未知人物 #1（22 个视频，47 段出场）" |
| **角色识别**（Character Recognition） | 匹配到具名身份：演员名 / 角色名 / 用户命名 | "钢铁侠 / Tony Stark / Robert Downey Jr." |

我们三层都做，逐级升级。

**F.2 多模态识别管线**

单纯靠人脸在视频里很容易翻车（侧脸、戴口罩、动漫角色没有真实脸）。我们融合 5 种信号：

```
关键帧抽取
    ↓
┌────────────────────────────────────────────────┐
│  1. 人脸检测 + ArcFace 特征 (真人)              │
│  2. 动漫脸检测 + AnimeFace ReID (动画/二次元)   │
│  3. 全身 ReID（OSNet）：服装 + 体型             │
│  4. 声纹 Diarization（pyannote / WeSpeaker）    │
│  5. 字幕实体识别：人名、称谓、对话归属          │
└────────────────────────────────────────────────┘
    ↓ 多模态融合（加权 + 时序一致性）
角色片段 (character_id, video_id, [start, end])
    ↓
增量聚类 + 跨视频合并
    ↓
角色档案（face / voice / aliases / 出场片段）
```

**关键点：时序一致性**——同一镜头连续帧应是同一角色，避免"一秒变脸"。

**F.3 命名来源（三层合一）**

| 来源 | 示例 | 触发条件 |
|---|---|---|
| **元数据库匹配** | TMDB / IMDB / Bangumi 已有演员表 | 视频识别为知名作品 |
| **字幕推断** | 字幕里"Tony, watch out!" → 镜头中说话人即 Tony | LLM 解析字幕 + 说话人对齐 |
| **用户命名** | 用户给某张脸打标签 → 全库回填 | 用户手动 |

三层任一命中即可，不命中则保持"未知角色 #N"。

**F.4 模型清单（追加）**

| 模型 | 用途 | 大小 | 后端 |
|---|---|---|---|
| RetinaFace | 真人人脸检测 | ~12 MB | ANE |
| ArcFace ResNet50 | 真人人脸特征 | ~95 MB | ANE |
| AnimeFace Detector + Recognizer | 动漫角色脸 | ~80 MB | ANE |
| OSNet | 全身 ReID（服装+体型） | ~20 MB | ANE |
| pyannote-3.1 | 说话人 Diarization | ~85 MB | Metal |
| Sentence-BERT (多语) | 字幕实体匹配 | ~120 MB | ANE |

**F.5 用户体验**

- **首次扫描**：后台自动跑，识别完成通知"在《复联》中识别到 12 个角色"
- **角色侧边栏**：媒体库左侧"角色"分组，每个角色显示头像 + 出场视频数
- **角色页**：进入后看到该角色所有视频片段，可一键跳到任意片段
- **批量命名**：识别为知名作品后，一键应用元数据库的演员-角色对照
- **修正机制**：用户可选中片段，"这不是 Tony" → 模型记住负样本
- **角色合并 / 拆分**：误聚到一起的可一键拆，被拆开的同一人可一键合
- **隐私模式**：可对个人录像禁用角色识别，只保留人脸聚类（不上传任何元数据库）

**F.6 角色驱动的高级玩法**

| 功能 | 描述 |
|---|---|
| **角色筛选** | "只看包含 Tony 的片段" — 跨剧集跨电影 |
| **角色对手戏** | 选 2 个角色 → 列出共同出场片段 |
| **角色高光集锦** | 自动剪辑某角色的 3 分钟混剪 |
| **角色台词搜索** | "Tony 说 I am Iron Man 的所有片段" |
| **角色出场时间轴** | 当前视频中该角色出现的所有时间段（进度条上标记） |
| **找演员的其他作品** | 选中演员 → 列出库里所有他演过的作品 |

**F.7 限制与坦诚说明**

- 真实人脸：戴口罩 / 极侧脸 / 严重模糊 → 识别率下降，依赖 ReID 兜底
- 动漫角色：换服装 / 同人脸不同发色（变身）→ 需要用户少量人工修正
- 双胞胎 / 高度相似：人脸不够，依赖声纹 + 上下文
- 完全本地：不依赖任何第三方人脸数据库（FaceNet 等仅用模型权重）


### 4.4 字幕子系统（P0）

> 字幕不是"附属功能"，而是看片体验的半壁江山。我们把它做成独立子系统：本地生成 + 在线下载 + AI 辅助对齐 + 编辑器闭环。

#### 4.4.1 设计原则

- **不让用户对时间轴**：AI 自动对齐是默认动作，手动只是兜底
- **多源融合**：在线源 + Whisper 本地生成 + 用户上传，全部进同一个字幕轨管理器
- **永远可回滚**：任何对齐 / 编辑动作都可撤销，每条字幕轨保留版本历史
- **隐私分级**：默认仅文件名 / 哈希出网搜索；用户可选择不联网

#### 4.4.2 字幕来源（三路并行）

**A. 在线字幕搜索下载**

| 源 | 强项 | 备注 |
|---|---|---|
| **OpenSubtitles** | 全球电影 / 剧集覆盖最广 | 官方 REST API，免 key 有限额，可接用户 key 提额 |
| **Subscene** | 双语字幕丰富 | 网页爬取（插件维护） |
| **射手 / 伪射手 / Assrt** | 中文字幕之王 | API 接口 |
| **字幕库 / SubHD** | 中文剧集 / 综艺 | 插件支持 |
| **Subtitles.org / Addic7ed** | 英美剧 | 插件 |
| **YouTube** | 自动 / 人工字幕 | 用户提供视频 ID 或 URL 时启用 |
| **Bilibili XML 弹幕**（独立分轨） | 中文社区 | 转字幕风格显示 |

匹配策略：
1. **文件哈希优先**（OSDB hash / OpenSubtitles 算法）— 命中即精准
2. **IMDB / TMDB ID 命中** — 通过元数据匹配
3. **文件名解析**（季 / 集 / 年份 / 分辨率） — 兜底
4. 命中后展示候选列表：源 / 语言 / 下载量 / 评分 / 上传时间，用户挑选

**B. Whisper 本地转写**
- 模型：tiny / base / small / medium / large-v3-turbo（按需下载）
- 默认 small（约 244MB，10 分钟视频 < 30s 完成）
- 支持 99 种语言识别 + 翻译到英文
- 输出词级时间戳（精度约 ±20ms）
- 可选语言模型微调：用户提供 1-2 集已有正确字幕，对该剧集做 prompt 微调，提升专有名词准确率

**C. 用户上传 / 拖入**
- 支持格式：SRT / ASS / SSA / VTT / SBV / LRC
- 拖到播放窗口或媒体库即自动关联
- 自动检测编码（GB2312 / GBK / UTF-8 / UTF-16），转为 UTF-8 存储
- 对齐流程默认进入"AI 辅助对齐"

#### 4.4.3 AI 辅助对齐（核心差异化）

在线下载的字幕、用户从其他版本拷来的字幕，时间轴往往与本视频对不上（差几秒到几分钟，甚至帧率不同导致渐进偏移）。本神设计了一套**多策略对齐管线**：

**对齐策略选择器（自动决策）**

```
拿到一个字幕文件
    ↓
[1] 长度 / 帧率检查
    └─ 字幕末尾 vs 视频末尾差 > 30s ?
        是 → 标记需要"全局缩放"
    ↓
[2] Whisper 锚点对齐（默认）
    └─ 抽取视频前 10min + 中间 10min + 末尾 10min 音轨
        → 本地 Whisper 转写得"时间锚点"
        → DTW 动态时间规整：把字幕文本映射到锚点时间
    ↓
[3] 静默检测对齐（轻量备选）
    └─ FFmpeg silencedetect 找出对话起止点
        → 与字幕的 N 条起止做最佳匹配
    ↓
[4] 互相关对齐（同语言才用）
    └─ 字幕原音轨已知 → 互相关找偏移
    ↓
[5] 用户手动锚点（兜底）
    └─ 在编辑器里给"第一句对话"和"最后一句对话"打两个锚点
        → 线性 / 分段插值
```

**精度目标**

| 场景 | 目标精度 |
|---|---|
| 同帧率字幕固定偏移 | ±50ms（自动） |
| 帧率不同（24 vs 23.976） | ±200ms（自动） |
| 不同剪辑版本（导演剪辑 / 院线版） | ±500ms（自动 + 提示用户复核） |
| 完全错位字幕 | 用户介入，AI 给候选 |

**翻译字幕的对齐**
- 翻译版往往句子断开方式不同，**不强行 1:1 映射**
- 改用"段落级对齐"：把视频按场景切，字幕按场景重新分配，再做内部线性插值
- LLM 辅助：当文本长度差异显著时，让 LLM 给出"哪几句翻译版字幕对应原文哪段"

#### 4.4.4 字幕编辑器

- 入口：字幕轨道 → 右键「编辑」/ 命令面板「编辑字幕」
- 三栏布局：
  - 左：字幕列表（双击跳转到该时间点）
  - 中：当前字幕预览 + 视频画面
  - 右：波形图 + 字幕条（可拖动起止点）
- 操作：
  - 整体偏移（`⌘[` / `⌘]` 各 50ms，`⌘⇧[` / `⌘⇧]` 各 500ms）
  - 帧率拉伸（输入"23.976→25"自动重计算）
  - 单条编辑：文本 / 起止 / 样式
  - 拆分 / 合并 / 删除 / 插入条
  - **AI 修订**（按钮）：让 LLM 修正错别字 / 翻译润色 / 标点规范化
- **波形可视化**：基于 ffmpeg 抽出的音频包络，红色高亮静默段，让用户对齐"开口说话"瞬间
- **快捷键全键盘可达**（继承 §4.5 的录制式自定义）

#### 4.4.5 多字幕轨道管理

每个 MediaItem 可挂多条字幕轨：

| 轨道属性 | 说明 |
|---|---|
| 来源（source） | online / whisper / user / embedded |
| 语言（lang） | ISO 639-1 |
| 类型（kind） | dialogue / forced / sdh / commentary |
| 偏移（offsetMs） | 全局偏移（不动原文件） |
| 帧率比（rateRatio） | 自动 / 手动 |
| 优先级（priority） | 用户排序 |
| 版本历史 | 每次保存生成快照，可回滚 |

播放器右下角字幕菜单：
- 当前轨 / 双语模式（主 + 次）/ 关闭
- 「同步偏移微调」滑条（±10s）
- 「在线搜索更多」直达
- 「AI 重新对齐」一键

#### 4.4.6 双语 / 多语字幕

- 主轨在下、次轨在上（位置可换）
- 颜色 / 字号独立配置
- 单条同步偏移（次轨可独立调整）
- 词典悬停：单击单词调出本地词典 / 海词 / 欧路（插件）

#### 4.4.7 字幕样式

- 字体 / 字号 / 颜色 / 描边 / 阴影 / 背景
- ASS 高级样式（卡拉 OK 着色 / 旋转 / 渐变）原生支持
- 预设：Netflix 风 / 苹果风 / 大字幕（车载）/ 学术风（带字典）/ 自定义
- 全屏 vs 窗口可独立设置

#### 4.4.8 用户体验流程

**最常见路径：看一部新下载的电影**
1. 双击播放 → 检测到没字幕 → toast「未找到字幕，正在搜索…」
2. 1-2 秒内：通知中心「找到 5 个候选 · 中文简体 / 英文 / 双语…」
3. 用户点选其一 → 自动下载 → AI 对齐 → 字幕出现
4. 全程不用手动操作时间轴

**离线 / 找不到字幕时**
- toast「在线搜索失败，是否本地生成（约 2 分钟）」→ 启动 Whisper

**字幕对不上时**
- 用户首选：右下角微调滑条（±10s 即时见效）
- 仍偏移：右键字幕 → 「AI 重新对齐」→ 跑全流程对齐管线
- 完全错位：进入编辑器，打两个锚点

#### 4.4.9 性能与隐私

| 指标 | 目标 |
|---|---|
| 在线搜索响应 | < 2s |
| AI 对齐 2 小时电影 | < 60s（M1） |
| Whisper 字幕 10min 视频 | < 30s（small） / < 90s（large） |
| 隐私模式 | 关闭联网搜索 / 仅本地 Whisper / 不上传任何样本 |

- 出网请求：仅文件哈希 + 元数据，绝不上传视频本身
- API Key：用户可填自己的 OpenSubtitles / Assrt key，更高速率
- 缓存：搜索结果缓存 7 天，避免重复请求

### 4.6 资源管理系统（P0）

#### 4.6.1 设计原则

- **永不真删**：默认走 macOS 回收站（`NSWorkspace.recycle`），可撤销
- **物理与逻辑分离**：媒体库"移除"≠ 文件删除，UI 明确区分
- **批量友好**：多选 + 批量操作 + 进度反馈 + 失败清单

#### 4.6.3 删除安全网（最关键）

```
用户按 ⌘⌫
    ↓
[选中 1 个]                [选中多个]
    ↓                          ↓
立即移到回收站         选中超过 10 个？
顶部 toast 5s 撤销        ↓ 是
                      二次确认弹窗
                      （列出前 5 个文件 + "等共 N 个"）
                          ↓ 确认
                      移到回收站 + 撤销 toast
```

- **撤销 toast**：「已移除 N 个文件 · 撤销」（5 秒，键盘 `⌘Z` 也能触发）
- **撤销栈**：30 分钟内的删除均可在 ⌘K → "最近删除"找回
- **永久删除**：必须 `⌘⇧⌫` + 弹窗，绝不一键真删
- **保护规则**：正在播放的文件 / 受保护文件夹（用户标记）拒绝删除

#### 4.6.4 文件夹与监视目录

- **快速打开文件夹**：媒体库左侧"文件夹"分组，列出所有监视根目录
- **添加文件夹**：`⌘⇧O` 或拖入侧边栏
- **快速跳转**：⌘K → 输入文件夹名直达
- **本地浏览模式**：⌘⇧L 切换"按文件夹层级浏览"（跳过 AI 分组）
- **同步状态指示**：每个文件夹旁显示扫描进度小圆点（点击展开队列）

#### 4.6.5 批量操作面板

触发：选中 ≥ 2 个文件后底部浮现操作条

- 移到回收站 / 永久删除 / 移动 / 复制 / 添加标签 / 修改海报 / 导出
- 进度条 + 失败重试 + 详细日志
- 大量操作（>100）走后台队列，可在通知中心查看进度

#### 4.6.6 同一视频多副本合并（Variant Grouping）

> 同一部影片在多个位置存在多份副本（NAS 4K / 本地 1080p / iCloud 手机录像）应在媒体库里**只显示一张卡片**，但每份副本都能独立访问。

**A. 合并的判定逻辑（多信号融合，置信度阈值）**

| 信号 | 权重 | 说明 |
|---|---|---|
| 内容指纹（头部 + 中段 + 尾部 SHA256 抽样） | 0.35 | 二进制完全一致 → 必合并 |
| 视频帧 pHash（关键帧感知哈希） | 0.30 | 不同码率 / 分辨率仍能匹配 |
| 音频指纹（Chromaprint） | 0.20 | 视频被重压但音轨一致 |
| 时长接近度（±1%） | 0.10 | 第一道粗筛 |
| 文件名 + 元数据相似度 | 0.05 | 辅助 |

- 综合得分 ≥ 0.85 → 自动合并
- 0.6 - 0.85 → 标记为"候选合并"，在媒体库标小角标，用户在重复管理面板确认
- < 0.6 → 视为不同视频

**B. Variant（副本）的数据模型**

```
MediaItem (逻辑视频，UI 一张卡片)
   ├─ Variant #1 · 4K HDR · 35GB · NAS:/Movies/Avengers.mkv  · 主副本
   ├─ Variant #2 · 1080p  · 8GB  · ~/Movies/Avengers-1080p.mp4
   └─ Variant #3 · 720p   · 1.5GB · iCloud:/Movies/手机录的.mov
```

- 主副本（primary）：默认播放它，规则可选——最高画质 / 最快可达 / 用户手动钉选
- 续播位置 / AI 字幕 / 摘要 / 标签 → **挂在 MediaItem 上**，副本之间共享
- 删除 / 重命名 / 移动 → **挂在 Variant 上**，互不影响

**C. 用户体验**

- 媒体库卡片右下角显示徽章 `2` / `3` 表示有几份副本
- 详情面板新增 "副本"标签页：列出每个副本（路径 / 大小 / 分辨率 / 来源 / 在线状态）
- 副本旁有 ⌘P 设为主副本 / 在 Finder 显示 / 删除该副本 / 拆出此副本（误合并时用）
- 智能播放：若主副本所在网盘断网，自动 fallback 到下一可达副本
- 离线下载：用户可指定"将主副本同步一份到本地"

**D. 重复管理面板**

- 设置 → 媒体库 → 重复管理
- 三个标签页：自动合并 / 候选待确认 / 误合并申诉
- 候选项展示对比缩略图 + 关键差异（时长差、分辨率差、码率差）
- 批量操作：全部合并 / 全部拒绝 / 逐项处理

#### 4.6.7 磁盘空间面板

- 设置 → 存储
- 统计：媒体总占用 / 缩略图缓存 / AI 模型 / 数据库
- 一键清理：缓存 / 已看完且超过 6 个月未播放的视频（仅提示，不删）
- 智能建议：「当前磁盘剩余 50GB，建议清理 12GB 缓存」

#### 4.6.8 文件完整性

- 后台校验：监视目录的文件是否被外部移动 / 删除
- 失踪文件：标记为"找不到"，提供「重定位」按钮（用户指认新位置后批量更新数据库）
- 损坏检测：播放失败时自动诊断，建议是否从库移除

#### 4.6.9 多副本下的文件管理（含网盘只读策略）

> 当用户对一张"合并后的卡片"执行删除 / 移动 / 重命名时，系统必须先问清楚"对哪一个副本下手"。

**A. 副本选择弹窗（Multi-Variant Action Sheet）**

触发条件：对存在 ≥ 2 个 Variant 的 MediaItem 执行任何文件级操作。

弹窗内容（自上而下）：

1. **顶部说明**："这部影片在 3 个位置都有副本，请选择此次操作的对象"
2. **副本清单**（每行一个，含勾选框）：
   - 缩略图 + 路径 + 大小 + 分辨率 + 来源徽章（本地 / NAS / iCloud / Plex…）
   - 在线状态点（绿 = 可达 / 灰 = 离线 / 红 = 失踪）
   - **若操作不被该副本支持，行变灰 + 右侧显示禁用原因**（如"网盘只读"）
3. **作用范围**：
   - ☐ 仅作用于所选副本
   - ☐ 同时从媒体库的 MediaItem 卡片中移除（仅删除时可见）
4. **快捷模式**：
   - 「全选可执行的副本」 / 「仅主副本」 / 「仅本地副本」
5. **底部按钮**：取消 / 确认（动态文案如"删除 2 个副本"）

**B. 默认策略（用户可在设置中改）**

| 操作 | 默认目标 |
|---|---|
| `⌘⌫` 删除 | 弹窗，默认勾选"主副本" |
| `⌘⇧⌫` 永久删除 | 弹窗，**强制勾选确认**，不可一键全删 |
| `⌘L` 重命名 | 弹窗，**只能选 1 个副本**（不允许跨副本批量改名） |
| `⌘⌥M` 移动到 | 弹窗 + 目标选择器，**网盘副本会被自动灰显** |
| `⌘E` 编辑标签 | 不弹窗（标签作用于 MediaItem，所有副本共享） |
| `⌘⇧M` 已看 / 未看 | 不弹窗（看片状态共享） |
| `⌘B` 收藏 | 不弹窗（共享） |

> 原则：**作用于"逻辑视频"的操作不弹窗；作用于"物理文件"的操作必弹窗。**

**C. 网盘副本的能力矩阵**

不同协议的可写性差异巨大，统一在一张表里管理：

| 协议 / 服务 | 读 | 删 | 重命名 | 移动 | 上传 |
|---|---|---|---|---|---|
| 本地磁盘 | ✓ | ✓ | ✓ | ✓ | ✓ |
| SMB（有写权限） | ✓ | ✓ | ✓ | ✓ | ✓ |
| SMB（只读挂载） | ✓ | ✗ | ✗ | ✗ | ✗ |
| NFS | ✓ | ✓ | ✓ | ✓ | ✓ |
| WebDAV（标准） | ✓ | ✓ | ✓ | ✓ | ✓ |
| **iCloud Drive** | ✓ | ✓ | ✓ | ✓ | ✓ |
| **Google Drive / OneDrive / Dropbox** | ✓ | ✓ | ✓ | **✗ 不支持移动** | ✓ |
| **阿里云盘 Open API** | ✓ | ✓ | ✓ | **✗ 不支持移动** | ✓ |
| **百度网盘** | ✓ | ✓（受限） | ✗ | ✗ | ✗（接口受限） |
| **Jellyfin / Plex / Emby** | ✓ | ✗ | ✗ | ✗ | ✗（媒体服务只读） |
| **DLNA / UPnP** | ✓ | ✗ | ✗ | ✗ | ✗ |
| **S3 / R2 / B2** | ✓ | ✓ | ✗（要复制+删除） | ✗ | ✓ |
| **FTP / SFTP** | ✓ | ✓ | ✓ | ✓ | ✓ |

**D. 网盘禁止移动的处理**

> 用户主动需求：**网盘上的视频，移动操作一律禁止**。

实现规则：

1. **UI 层禁用**：副本选择弹窗中，所有网盘副本的"移动"操作灰显，悬停提示"网盘副本不支持移动"
2. **快捷键拦截**：在网盘副本上按 `⌘⌥M` 直接弹 toast「网盘副本不支持移动操作」
3. **Finder 拖拽拦截**：拖一个网盘副本到任意目标 → 提示"如需迁移到本地，请使用「下载到本地」"
4. **替代方案引导**：在禁用提示旁附操作建议——
   - "下载到本地后再操作"
   - "先复制到目标位置，再从源位置删除"（需用户两步确认）
5. **批量场景**：批量操作勾选了网盘副本 + 移动操作 → 弹窗提示"X 个网盘副本无法移动，将自动跳过"
6. **管理员模式**（隐藏开关，专家用户可启用）：可解锁网盘移动，但每次确认弹窗会警告"该操作可能因协议限制失败或导致文件丢失"

**E. 操作失败的兜底**

任何针对副本的操作失败 → 不影响 MediaItem 本身：

- 弹窗显示「2 个副本删除成功，1 个失败（NAS 离线）」
- 失败副本进入「待重试」队列，下次该网盘上线时自动重试
- 用户可在设置 → 操作历史 中查看与撤销

**F. 副本拆分（误合并修正）**

如果系统把两个不同视频错误合并：
- 详情页 → 副本标签页 → 选中 → 「这不是同一视频，拆出来」
- 拆出后视为独立 MediaItem，重新参与续播 / 标签等
- 拆分动作记入 AI 学习样本，避免下次再误合

### 4.7 网盘与远程存储（P0）

> 让本地播放器变成"全屋 / 全网媒体中心"。视频不必在硬盘上，体验和本地一样。

#### 4.7.1 设计原则

- **本地与远程一视同仁**：媒体库、AI、续播、字幕全部对远程文件平等支持
- **流式播放优先**：大文件不强制全量下载，能 seek 就 seek
- **挂载即视图**：每个网盘 = 媒体库左侧一个文件夹分组，自动扫描入库
- **凭据安全**：所有账号 / 密码 / Token 走 macOS Keychain，永不明文落盘
- **离线可用**：常看视频可标记"离线缓存"，断网仍可看
- **断点续传**：下载、扫描、AI 索引全部支持中断恢复

#### 4.7.2 协议与服务支持

**第一梯队 P0（首发）**

| 类型 | 协议 / 服务 | 说明 |
|---|---|---|
| 局域网 | **SMB / CIFS**（v2 / v3） | NAS、Windows 共享、macOS 共享 |
| 局域网 | **AFP** | 老 Mac / TimeMachine 风格 NAS |
| 局域网 / 互联网 | **WebDAV / WebDAV+HTTPS** | 群晖、坚果云、TeraCloud、可道云 |
| 局域网 | **NFS v3 / v4** | Linux NAS、ESXi 数据存储 |
| 媒体服务 | **DLNA / UPnP** | 智能电视、群晖 Media Server |
| 媒体服务 | **Jellyfin** API | 开源媒体中心 |
| 媒体服务 | **Plex** API（只读） | 用户自己的 Plex 库 |
| 媒体服务 | **Emby** API | Plex 替代 |

**第二梯队 P1（首发后 1-2 月）**

| 类型 | 服务 | 说明 |
|---|---|---|
| 公有云 | **iCloud Drive** | 系统级集成，零配置 |
| 公有云 | **Google Drive** | OAuth 登录 |
| 公有云 | **OneDrive** | 个人 / 商业版 |
| 公有云 | **Dropbox** | OAuth |
| 国内云 | **阿里云盘**（Open API） | 转存 + 流播 |
| 国内云 | **百度网盘**（开放接口） | 受平台速度限制 |
| 国内云 | **115 网盘** | 通过 WebDAV 中继 |
| 国内云 | **天翼云盘 / 移动云盘** | WebDAV |
| 对象存储 | **S3 兼容**（AWS / R2 / B2 / MinIO） | 自建 / 备份用户 |
| 对象存储 | **阿里 OSS / 腾讯 COS** | 国内自建 |
| 协议 | **FTP / FTPS / SFTP** | 老派但管用 |

**第三梯队 P2（按需 / 插件）**

迅雷网盘、夸克网盘、123 网盘等流量受限的国内服务，走 **插件机制**，由社区维护，避免主程序被特定平台 ToS 限制。

#### 4.7.3 远程播放策略

**A. 直接流式（首选）**
- SMB / NFS / WebDAV 局域网：直接喂给 FFmpeg，原始码率播放
- 公网 WebDAV / S3：HTTP Range 请求 seek，预读 30s 缓冲
- 媒体服务（Jellyfin / Plex / Emby）：调原生流接口，支持 transcode

**B. 智能预取**
- 进度条悬停预览时，按需拉取目标位置 1 个 GOP（不下整段）
- 全屏播放时预取后续 60s
- 用户网速低于码率：自动提示"启用转码 / 下降画质 / 切到 SD 版本"

**C. 离线缓存**
- 媒体库右键"离线可用"→ 后台下载到本地
- 设置：缓存上限（默认 20GB，LRU 淘汰）
- 缓存文件加密（FileVault 之上加一层 AES-GCM）

**D. 转码代理（仅 Jellyfin / Plex / Emby）**
- 支持设备能力协商，让服务端转码到 Mac 能直接硬解的格式
- 局域网内优先 4K 直通；外网回落 1080p

#### 4.7.4 AI 在远程文件上的工作方式

| 任务 | 远程策略 |
|---|---|
| 扫描入库 | 流式读取头部，提取容器/编码/时长，**不下整片** |
| 缩略图 | 流式 seek 抽 10 帧，本地缓存 PNG |
| Whisper 字幕 | 后台拉取音轨（约视频 5%），本地推理 |
| CLIP 嵌入 / 角色识别 | 抽取 20 关键帧（每帧 ~200KB），不下整片 |
| 增量 | 文件 mtime / etag 变化才重算 |

> **核心：网络代价由元数据/抽帧承担，不要求用户下完整片**

#### 4.7.5 用户体验

**添加网盘流程**
1. 设置 → 存储 → 添加网盘
2. 选类型（SMB / WebDAV / 阿里云盘…）
3. 填写主机 / 凭据，**测试连接**按钮即时反馈
4. 选挂载子目录（可只挂载 `/Movies`）
5. 命名 → 完成
6. 后台开始扫描，通知中心提示进度

**侧边栏挂载点**
- 每个网盘一行，带在线 / 离线 / 同步中圆点
- 右键：浏览 / 重新扫描 / 编辑 / 卸载
- 离线时显示已缓存的视频，未缓存的灰显

**断网降级**
- 播放中断网：暂停 + toast「网络中断，已缓存 12s」
- 自动尝试重连，恢复后从断点继续
- 完全不可用时，提示用户切换离线模式

#### 4.7.6 性能与限制

| 项 | 目标 |
|---|---|
| SMB 4K H.265 局域网 | 流畅直通（千兆网） |
| WebDAV 1080p 公网 | 50Mbps 带宽以上流畅 |
| 阿里云盘 4K | 受官方接口速度限制，自动降码率提示 |
| 网盘扫描速度 | > 200 文件/分钟（取决于服务端） |
| Keychain 项数 | 每个网盘 1 项，撤销账号即整体清除 |

#### 4.7.7 安全与隐私

- **凭据**：仅存 macOS Keychain，App 卸载随系统机制清理
- **OAuth Token**：refresh_token 加密存储，access_token 仅内存
- **元数据出网**：默认不向任何第三方上报；启用 TMDB 等插件时仅传文件名
- **私密目录**：用户可标记某网盘"不参与 AI 索引 / 不显示在最近"
- **审计日志**：设置 → 隐私 → 查看「最近 30 天网盘访问记录」

#### 4.7.8 故障排查

- 内置 **网盘诊断面板**：连通性 / 带宽测速 / 编解码兼容性 / Range 支持
- 常见问题（如 SMB v1 被禁、WebDAV chunked transfer 不支持 seek）给出引导
- 一键导出诊断报告（脱敏后）便于反馈

## 5. 界面设计原则

### 5.1 视觉语言

| 元素 | 规范 |

| 动画 | 系统标准 spring，时长 0.3s |

### 5.2 三大主界面

**① 启动屏**
- 极简：居中 Logo + 拖入提示 + 最近播放（3 个海报）
- 不做引导教程，跟着 macOS 直觉走

**② 媒体库**
- 左：分组侧边栏（最近 / 在看 / AI 分类 / 人物 / 标签）
- 中：网格 / 列表
- 右：选中视频时滑入详情面板（海报 / 简介 / AI 摘要 / 章节）

**③ 播放器**
- 完全沉浸，光标移动控制条由底部浮现（高斯模糊背景）
- 控制条只显示：播放 / 进度 / 音量 / 字幕 / 全屏
- 高级功能藏在 ⌘K 命令面板中

### 5.3 命令面板（灵魂）
- 快捷键：⌘K
- 模糊匹配所有功能 + 媒体库 + AI 搜索
- 类似 Raycast / Linear 的极致体验

## 7. 技术架构概要

```
┌────────────────────────────────────────────────────────┐
│  UI Layer  ·  SwiftUI + AppKit + Metal                 │
├────────────────────────────────────────────────────────┤
│  Application Logic  ·  Swift 5.9 / Swift Concurrency   │
├──────────────────┬──────────────────┬──────────────────┤
│  Playback Core   │  AI Engine       │  Media Library   │
│  (FFmpeg +       │  (Core ML +      │  (SQLite +       │

├──────────────────┴──────────────────┴──────────────────┤
│  Plugin Host  ·  JavaScriptCore + Swift Sandbox        │
├────────────────────────────────────────────────────────┤
│  macOS APIs  ·  Metal / VideoToolbox / Core ML / ANE   │
└────────────────────────────────────────────────────────┘
```

### 7.1 模块边界
- **PlaybackKit**（独立 framework）：解码 / 渲染 / 同步，对外暴露 `Player` 协议
- **MediaKit**：扫描 / 元数据 / 数据库
- **AIKit**：模型加载 / 推理 / 任务队列
- **PluginKit**：JS 引擎 / 沙箱 / 权限
- **HiVideo App**：组装上述模块 + UI

### 7.2 数据存储
- 应用数据：`~/Library/Application Support/HiVideo/`
- 主数据库：`library.sqlite`（含 sqlite-vec 扩展存嵌入）
- 缩略图缓存：`~/Library/Caches/HiVideo/thumbs/`
- 模型：`~/Library/Application Support/HiVideo/models/`
- 配置：`~/Library/Preferences/com.hikari.HiVideo.plist`
